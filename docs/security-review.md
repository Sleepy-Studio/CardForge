# M7 security review

Reviewed at the end of M7 against the closed-alpha threat model: untrusted
players on the public internet, one operator team, no payments. Each area
lists the control and how it is verified.

| Area                            | Control                                                                                                                                                                                                                                               | Verified by                                                                                                       |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Account identity                | Hashed opaque session cookies; no client-supplied account IDs anywhere (`/api/me`, room tickets).                                                                                                                                                     | `journey-smoke`: legacy header ignored, legacy routes 404, forged tickets and `accountId` join options rejected.  |
| Deck ownership                  | Rooms load decks by `(ticket account, deckId)` and require legal, fully owned decks with unlocked Leaders.                                                                                                                                            | `journey-smoke`: unowned deck refused with a player-readable reason.                                              |
| Reward settlement               | One `(match, account)` receipt inside the wallet/XP transaction; room-level promise guard; failed settlement retried (receipts make retries safe), then `critical`.                                                                                   | `journey-contract.test` (concurrent double settle pays once, memory and Postgres); `journey-smoke` balance check. |
| Ranked settlement               | Existing per-match receipt with row locks; outcome recorded once (`completed_at IS NULL` guard).                                                                                                                                                      | Contract test; `journey-smoke` wins + losses = 1.                                                                 |
| Invite codes                    | 6 characters from a 32-symbol alphabet (≈10⁹), 15-minute expiry, one guest, one match, creation and lookup rate-limited per account.                                                                                                                  | Contract test; `journey-smoke` third account and spent code refused.                                              |
| WebSocket payloads              | Strict Zod intent schema without `playerId`; 16 KiB frame cap; per-connection budget (40 messages / 5 s by default).                                                                                                                                  | `session.test`, `m7.test` (every legal command round-trips), limiter observed in `/metrics`.                      |
| Malformed or duplicate commands | Rejected without state change; the client keeps one command in flight.                                                                                                                                                                                | `session.test`; browser smoke.                                                                                    |
| Replay access                   | Participants only (admins any); completed matches only; public or own-seat perspective; seeds and deck order never sent.                                                                                                                              | `m7.test` hidden-hand and tamper checks; `journey-smoke` 403/404 cases.                                           |
| Admin and operations            | Admin role or ≥ 32-character bearer token compared in constant time; no default token; audit actor derived server-side; `/metrics` gated in production. Admin is granted only by an operator or a verified Discord ID, never by a registration email. | `operations-smoke` (promotion and demotion).                                                                      |
| CORS                            | Only allow-listed origins receive CORS headers; `null` and foreign origins get none (fixed a Colyseus default that echoed them with credentials).                                                                                                     | `journey-smoke` null-origin probe.                                                                                |
| CSRF                            | `SameSite=Lax` cookies, Origin allow-list on every mutating request, JSON-only bodies.                                                                                                                                                                | `journey-smoke` foreign-origin POST → 403.                                                                        |
| Session cookies                 | `HttpOnly; SameSite=Lax; Secure` (production), 30-day sliding expiry, logout and logout-everywhere revoke rows.                                                                                                                                       | `m7.test`, `journey-smoke` logout.                                                                                |
| Password handling               | scrypt with per-password salt; decoy hash for unknown emails; per-IP and per-email rate limits; single-use hashed reset/claim codes that revoke sessions.                                                                                             | `m7.test`, `operations-smoke`.                                                                                    |
| Post-login redirects            | `next` limited to same-origin paths without backslashes, on the server and in the login form.                                                                                                                                                         | `m7.test`.                                                                                                        |
| OAuth                           | `identify` scope only; state bound to a signed HttpOnly cookie; relative-path `next` only.                                                                                                                                                            | `discord-smoke`, `m7.test`.                                                                                       |
| SQL injection                   | Every query uses the `postgres` tagged-template parameterisation; the only `unsafe` call runs repository migration files.                                                                                                                             | Code review.                                                                                                      |
| Logging exposure                | Recursive redaction of password/secret/token/cookie/authorization/credential keys; access logs record path without query strings.                                                                                                                     | `m7.test` redaction test.                                                                                         |
| Rate limits                     | Auth 200 / 10 min / IP (venue-friendly) + 10 / 10 min / email; player writes 120 / min / account; invites 20 / h / account.                                                                                                                           | `m7.test`; configurable via environment.                                                                          |

## Accepted risks for the closed alpha

- Registration reveals whether an email is already registered (409). Invite
  mode limits who can probe.
- No email verification; password recovery is support-assisted.
- The web app sets `X-Frame-Options`, `nosniff`, a referrer policy, and a
  permissions policy, but no Content-Security-Policy yet (Next.js inline
  bootstrap scripts need a nonce setup).
- Rate limits and rooms are process-local, which is correct for the single
  replica the alpha runs.
